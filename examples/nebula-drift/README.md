# Example — Nebula Drift (a real `/spec` run, captured)

This is the **official worked example** of `/spec`: a complete, *probe-verified*
spec produced by running the skill end-to-end on a real-ish brief ("build a 2D
space shooter"). Everything here was generated by the `/spec` loop — investigate →
present → ask → decide → probe → persist → closure — and then frozen so you can
read the output and **re-run the evidence yourself**.

It is not a toy walkthrough. The probes actually execute, the gates actually go
green or red, and one human assumption is actually refuted on contact with
reality.

## The scenario, in one breath
The surface ask was *"build a 2D space shooter."* The scout reframed it to the
real problem — **a snackable browser game that goes from click to fun in ~10
seconds and gives a reason to replay** — then drove two phases to closure:

- **Phase 1 (sealed):** single-player browser core loop. The human *assumed a
  native desktop build via Godot*; the scout probed reality, **`godot` was not
  present (gate G0 went red)**, and the decision pivoted to a browser build
  (PixiJS + Vite). Toolchain/port/asset gates verified green.
- **Phase 2 (decisions locked):** trusted online multiplayer. The real question
  wasn't "which transport" but "**who owns the truth**" — a shared scoreboard
  forces a **server-authoritative** model, which makes the Phase-1 `localStorage`
  high score (R5) obsolete (superseded by R7). A **dependency-free WebSocket
  probe (G6)** verifies the transport can bind, handshake, and round-trip.

## What's in here
```
SPEC.md                         the authoritative, highest-priority spec (the deliverable)
CLAUDE.md                       SPEC-AUTHORITY block — tells any agent to read SPEC.md first
verify.sh                       runs every probe + 23 assertions; exit 0 == green
.spec/
  STATE.md                      resumable progress ledger (phase/step/next_action)
  knowledge/                    pinned reconnaissance (what was chosen, vs what, and why)
    render-framework.md           PixiJS (with versions, as-of a date)
    build-tool.md                 Vite
    realtime-transport.md         server-authoritative over ws (Phase 2 decision)
  probes/                       runnable gate probes, each with a negative control
    G0-godot.sh  G1-node-toolchain.sh  G2-devport.sh  G3-assets.sh  G6-ws-transport.sh
  evidence/                     raw probe output, each stamped with real OS UTC time
```
(No `node_modules`, no app code — `/spec` is **Gate 1**: it fixes the contract and
its evidence, not the implementation.)

## Reproduce the evidence
```bash
cd examples/nebula-drift
./verify.sh            # runs all probes + 23 assertions; prints ALL PASS / exit 0
```
You'll see the green gates pass, **G0 deliberately go red**, every negative
control fire, and every evidence log carry a real `when: …Z` UTC stamp. Requires
`bash`, `node` (≥ a modern LTS), and `python3`.

# Objective value assessment

Can these artifacts serve as *an important project-initial-phase deliverable* and
*a spec standard*? Assessed honestly, including the limits.

### Where it clears the bar

1. **It is decision-grade, not aspirational.** Every load-bearing claim is tied
   to a gate, and every gate to a runnable probe with raw evidence. "PixiJS, not
   native" isn't an opinion here — G0 went red and the log proves it. That is the
   difference between a spec a team can *act on* and a wish list.
2. **It refuses to rubber-stamp.** Every probe carries a **negative control** and
   `verify.sh` asserts the refuted gate *actually fails*. A green therefore means
   something — the single most common failure mode of "we have tests/gates" specs
   is avoided by construction.
3. **It is honest about what it doesn't know.** The 60-FPS performance gate (G4)
   is left **open**, not faked green, because it can't be probed before a
   prototype exists. A standard that can represent "verified", "refuted", and
   "honestly unknown" distinctly is more trustworthy than one that only knows
   "done".
4. **It survives time and context resets.** Every record is stamped with real OS
   UTC time (never fabricated), and `STATE.md` makes the run resumable — a fresh
   agent with a small context window can rehydrate and continue. This is what lets
   it be a *living* initial-phase document rather than a snapshot that rots.
5. **It governs altitude.** The spec fixes capabilities ("score always visible"),
   not pixels ("purple-gradient HUD top-right") — the latter is explicitly pushed
   below the spec line to execution. That keeps the document stable as
   implementation churns, which is exactly what an initial-phase contract needs.
6. **It models change correctly.** Phase 2 doesn't quietly edit Phase 1; R5 is
   **superseded** with a cited reason and R7 is added. The ledger of *why a
   decision was replaced* is preserved, which is what makes it auditable later.

### Where it is bounded (and says so)

- **Probes prove a lower bound, not correctness.** G6 proves transport
  *reachability and round-trip on this machine* — not latency under load, not the
  production wire format. The spec states this coverage limit rather than
  overclaiming; a reader must not read "G6 ✅" as "netcode done".
- **Environment-shaped greens.** Greens are "as of" a host and a date (`vm`,
  2026-06-29). They are re-runnable, which is the mitigation, but they are not
  portable guarantees — re-verify on the target environment.
- **Some gates are necessarily weak.** G5 (localStorage) was a non-probed design
  assertion, explicitly labeled WEAK, and later superseded. The standard's value
  depends on the author *labeling* weak gates honestly — the format enables that
  but can't enforce judgment.
- **It is a starting contract, not a plan.** There are no estimates, no task
  breakdown, no staffing. As a *spec standard* it's strong; as a *project plan*
  it is deliberately out of scope (execution and skill-extraction are Gate 2+).

### Verdict
As a **project-initial-phase deliverable**: yes — it gives a team a feasible,
evidence-backed contract, a clear in/out scope, a recorded decision trail, and a
list of the honestly-open questions to resolve next. That is more than most
kickoff documents deliver. As a **spec standard**: yes, with the discipline it
encodes made explicit — *every gate probe-backed, every probe able to go red,
every record time-stamped, weakness labeled not hidden, supersedes cited.* The
format's worth is exactly proportional to that discipline, and this example exists
to demonstrate the discipline is enforceable (`verify.sh` is the proof).
